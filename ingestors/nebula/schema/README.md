# Nebula Unified Schema Directory

This directory contains the unified Nebula Graph schema that combines all ontologies (POI, People, People Locations) into a single space.

## Files

- `nebula_{space_name}_schema.ngql` - Current unified schema file (generated by default)
- `nebula_{space_name}_schema_YYYYMMDD_HHMMSS.ngql` - Timestamped schema files for versioning

Examples:
- `nebula_unified_schema.ngql` - Default space name
- `nebula_tourism_space_schema.ngql` - Custom space name
- `nebula_event_impact_space_schema.ngql` - Custom space name

## Usage

### Generate unified schema (default space name):
```bash
cd ingestors/nebula
python generic_schema_generator.py
```

### Generate schema with custom space name:
```bash
cd ingestors/nebula
python generic_schema_generator.py --space-name tourism_space
```

### Generate timestamped schema:
```bash
cd ingestors/nebula
python generic_schema_generator.py --timestamped
```

### Generate timestamped schema with custom space name:
```bash
cd ingestors/nebula
python generic_schema_generator.py --space-name event_impact_space --timestamped
```

### Generate schema with custom output:
```bash
cd ingestors/nebula
python generic_schema_generator.py --output schema/custom_schema.ngql
```

### List loaded ontologies:
```bash
cd ingestors/nebula
python generic_schema_generator.py --list-ontologies
```

## Schema Structure

The unified schema includes:
- **Single Space**: `{space_name}` containing all data (default: `unified_space`)
- **All Entities** from all ontologies:
  - **POI Ontology**: `POI`, `POI_TYPE`
  - **People Ontology**: `PERSON`, `ROLE`
  - **People Locations Ontology**: `POSITION_PING`, `TICKET_ENTRY`
- **All Relationships** from all ontologies:
  - **POI**: `IS_OF_TYPE`
  - **People**: `HAS_ROLE`
  - **People Locations**: `EMITTED`, `ENTERED`, `AT_POI`
- **Unified Indexes** with ontology prefixes for performance

## Benefits of Unified Schema

### Cross-Ontology Queries
- Query across all domains in a single space
- No need for cross-space operations
- Simplified data relationships

### Unified Data Management
- Single space for all tourism and event impact data
- Consistent data model across all domains
- Easier data ingestion and maintenance

### Performance Optimization
- All indexes in one space
- Optimized for complex multi-domain queries
- Reduced query complexity

## Example Queries

### Cross-Domain Analysis
```cypher
// Find all tourists who visited a specific POI
MATCH (p:PERSON)-[:HAS_ROLE]->(r:ROLE {name: "tourist"})
MATCH (p)-[:ENTERED]->(t:TICKET_ENTRY)-[:AT_POI]->(poi:POI {name: "Museum"})
RETURN p, poi, t.timestamp;
```

### Movement Pattern Analysis
```cypher
// Analyze movement patterns by role
MATCH (p:PERSON)-[:HAS_ROLE]->(r:ROLE)
MATCH (p)-[:EMITTED]->(pos:POSITION_PING)
RETURN r.name, count(pos) as position_count
ORDER BY position_count DESC;
```

## Versioning

Use timestamped schemas to track changes over time. Each timestamped file includes the generation timestamp in the filename format: `nebula_{space_name}_schema_YYYYMMDD_HHMMSS.ngql`

## Schema Committer

Use the schema committer to deploy schemas to Nebula Graph:

```bash
# Preview what would be executed
./commit_schema.sh --dry-run schema/nebula_unified_schema.ngql

# Test with mock mode
./commit_schema.sh --mock schema/nebula_unified_schema.ngql

# Commit to database
./commit_schema.sh schema/nebula_unified_schema.ngql
```

For more details, see the commit_schema.py script and commit_schema.sh wrapper.

## Integration

This unified schema replaces the need for separate schemas when:
- Cross-ontology queries are required
- Unified data management is preferred
- Simplified deployment is needed
- Complex tourism and event impact analysis is performed
